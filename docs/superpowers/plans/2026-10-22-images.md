# Images dans le presse-papiers — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Capturer les images copiées (captures d'écran, « Copier l'image », fichier image copié dans l'Explorateur), les afficher en miniature dans l'historique, les recoller, les mettre en favori, les exporter, et les annoter dans un éditeur intégré.

**Architecture:**
- Un module Rust pur, `imaging.rs`, regroupe tout ce qui est image : décodage et encodage PNG, miniature, hash des pixels, limites, et la règle « texte d'abord » de choix de la source capturée.
- `db.rs` stocke les PNG dans une table `images` liée à `items` (1 ligne `items` de `kind = 'image'` et `content = ''`).
- Le watcher capture et écrit les images comme il le fait pour le texte.
- Côté frontend, la liste affiche des miniatures chargées à la demande. Un nouveau fichier `annotate.ts` contient l'éditeur `<canvas>`.

**Tech Stack:** Rust (Tauri 2, rusqlite, arboard 3.6, clipboard-win 5, crate `image` 0.25, crate `base64` 0.22), TypeScript vanilla, `<canvas>` 2D.

**Spec:** `docs/superpowers/specs/2026-10-22-images-design.md`

## Global Constraints

- Tout en français : commentaires Rust et TS, textes d'interface, messages de commit.
- Le thread watcher est l'unique propriétaire du presse-papiers : aucune lecture ni écriture d'arboard ou de clipboard-win hors de `watcher.rs`.
- Ajouter une commande touche 3 endroits : `commands.rs`, `invoke_handler` de `lib.rs`, wrapper dans `api.ts`.
- `Item` d'`api.ts` reste le miroir exact de `db::Item`.
- Après tout changement de favoris, appeler `crate::refresh_tray_menu(&app)`.
- Verrous : `lock().unwrap_or_else(|e| e.into_inner())`.
- Aucun envoi réseau ; frontend sans framework ni bibliothèque de dessin.
- Valeurs fixées par la spec :
  - images ignorées au-delà de **50 mégapixels** ou si le PNG dépasse **20 Mo** ;
  - budget des images non épinglées : **200 Mo** ;
  - miniature d'environ **200 px** de large ;
  - palette de 5 couleurs : rouge `#e5484d` (défaut), jaune `#f5c451`, vert `#30a46c`, bleu `#5865f2`, noir `#111111` ;
  - extensions de fichier reconnues : `png`, `jpg`, `jpeg`, `gif`, `bmp`, `webp` ;
  - export JSON en `version: 2`, fichiers `version: 1` toujours importables.
- **Écart assumé avec la spec, signalé au propriétaire :** l'annotation s'ouvre par **Ctrl+E**, par un bouton « Annoter » au survol de la ligne, ou par « Modifier » dans le favori déplié. Deux raisons :
  - la recherche a le focus, donc une touche E seule s'écrirait dans la recherche ;
  - le simple clic copie et cache la fenêtre, donc un double-clic n'est pas exploitable.

## Review Focus

1. **Copie de cellules Excel ou d'un paragraphe Word** (texte + HTML de tableau + bitmap) : seul le texte entre dans l'historique, aucune entrée image. → test `capture_source_excel_keeps_text` (Task 1).
2. **Une image recollée par copicol, ou la même capture recopiée** : pas de doublon, l'élément remonte en tête. Windows peut renvoyer des octets légèrement différents de ceux écrits ; le watcher hashe donc ce qu'il **relit** après écriture. → test `image_dedupe_moves_to_top` (Task 2) et étape de relecture (Task 4).
3. **Fichier corrompu, PNG tronqué, base64 invalide à l'import** : élément ignoré et compté comme tel, jamais de panique. → tests `decode_garbage_is_err` (Task 1) et `import_v2_skips_invalid_image` (Task 3).
4. **Ouvrir la fenêtre avec beaucoup d'images** : `list_items` ne transporte aucun blob, seules les miniatures sont chargées, une par une. → test `list_items_has_image_meta_without_blob` (Task 2).
5. **Supprimer, purger ou vider l'historique** : le PNG part aussi, sans orphelin qui ferait grossir la base. → test `deleting_item_removes_image_row` (Task 2).

  - `pub fn capture_source(text: Option<&str>, html: Option<&str>, has_image: bool) -> CaptureSource`

- **Schéma** (dans `init`, migration non destructive) :

  ```sql
  CREATE TABLE IF NOT EXISTS images (
      item_id INTEGER PRIMARY KEY,
      png BLOB NOT NULL,
      thumb BLOB NOT NULL,
      width INTEGER NOT NULL,
      height INTEGER NOT NULL,
      bytes INTEGER NOT NULL
  );
  CREATE TRIGGER IF NOT EXISTS items_delete_image AFTER DELETE ON items
  BEGIN DELETE FROM images WHERE item_id = OLD.id; END;
  ```

  Le trigger couvre `delete_item`, `clear_history` et `prune` sans les toucher.
- **Lecture** : `ITEM_COLUMNS` gagne `images.width, images.height, images.bytes`, et toutes les requêtes d'items lisent `FROM items LEFT JOIN images ON images.item_id = items.id`. Les noms de colonnes ne se recouvrent pas. `row_to_item` construit `image` quand `width` n'est pas NULL.
- **Insertion** : `insert_or_touch_image` fait `INSERT … ON CONFLICT(hash) DO UPDATE SET created_at` avec `content = ''` et `kind = 'image'`. Si l'item est nouveau, il insère la ligne `images` avec `bytes = png.len()`, puis appelle `prune` et `prune_image_budget`.
- **`fn prune_image_budget(conn: &Connection, budget: i64) -> rusqlite::Result<()>`** (privée, appelée avec `MAX_IMAGE_BUDGET`) : supprime les items non épinglés d'images dont le cumul dépasse le budget, des plus récentes aux plus anciennes :

  ```sql
  DELETE FROM items WHERE id IN (
    SELECT id FROM (
      SELECT items.id, SUM(images.bytes) OVER (ORDER BY items.created_at DESC, items.id DESC) AS cum
      FROM items JOIN images ON images.item_id = items.id WHERE items.pinned = 0
    ) WHERE cum > ?1)
  ```

- **Garde-fous** :
  - `set_kind` renvoie `Err` si `is_image(id)` ;
  - `update_content` renvoie `Err` si `is_image(id)` ;
  - `ALL_KINDS` ne change pas (pas de `"image"`).
- **Favoris** : `insert_favorite_image` reprend le modèle de `insert_favorite` (`ON CONFLICT(hash) DO NOTHING`, `true` si créé).

### Task 4: Capture et écriture d'images dans le watcher

**Files:**
- Modify: `src-tauri/src/watcher.rs`, `src-tauri/src/commands.rs` (`copy_item`), `src-tauri/src/lib.rs` (`copy_favorite_to_clipboard`, `tray_label_fallback`)

**Interfaces:**

- Produces:
  - nouvelle variante `WatcherMsg::WriteImage { image: imaging::Rgba, ack: Sender<Option<String>> }`. L'ack renvoie le hash de l'image **relue** dans le presse-papiers après écriture, ou `None` en cas d'échec.
  - `pub fn write_item_to_clipboard(app: &AppHandle, id: i64) -> Result<(), String>` dans `watcher.rs` : lit l'item, envoie `Write` (texte) ou `WriteImage` (PNG décodé), attend l'ack (1 s pour du texte, 3 s pour une image), puis appelle `db::mark_used`.
  - `pub fn write_image_to_clipboard(app: &AppHandle, image: imaging::Rgba) -> Result<Option<String>, String>` : utilisée par la Task 5.

- [ ] **Step 1: Écriture**

`WriteImage` appelle `clipboard.set_image(arboard::ImageData { width, height, bytes: Cow::Owned(pixels) })`.

Ensuite, le watcher relit aussitôt l'image avec `clipboard.get_image()` et calcule `imaging::image_hash` sur la relecture. Il met `last_hash` à cette valeur et la renvoie dans l'ack. Raison : Windows convertit en DIB, et les octets relus peuvent différer légèrement de ceux écrits ; sans cette relecture, le poll suivant réinsérerait l'image.

3. Décider avec `imaging::capture_source`.
   - **`Text`** : chemin actuel, inchangé.
   - **`Image`** : convertir `ImageData` en `Rgba`, refuser si `!within_limits` (log `warn` comme pour le texte trop gros), calculer le hash, comparer à `last_hash` puis le mettre à jour. Ensuite `db::new_image` (refus et `warn` si le PNG dépasse 20 Mo), `insert_or_touch_image`, et émettre `clipboard-changed`.
   - **`Nothing`** : lire la liste de fichiers (`clipboard.get().file_list()` en arboard 3.6, sinon `clipboard_win::formats::FileList`). Si elle contient **exactement un** chemin et que `is_image_path` est vrai, lire le fichier (`std::fs::read`, refus au-delà de 50 Mo), puis `imaging::decode` et le même chemin que `Image`.
   - Le hash de dédoublonnage d'un fichier se calcule sur le **chemin et la date de modification** avant décodage : on ne relit pas le fichier à chaque poll de 400 ms.
4. Le décodage d'un fichier ou d'une image invalide est ignoré (log `warn`), sans panique.

L'encodage PNG est lourd, mais il ne se fait qu'au changement de hash, jamais à chaque poll.
